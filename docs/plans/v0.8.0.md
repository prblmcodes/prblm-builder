## 2. Technical approach

### F1 — margin merging (`frames.js`, `builder.js`)
- `measure()` also returns `mt` / `mb`: the top margin of the first and the bottom margin of
  the last measured element, and `collapse`: whether the section's container lets margins
  merge (plain shell → yes; preview template → the markers' parent is display `block` /
  `flow-root`-less normal flow, not flex / grid / with padding or border at that edge).
- After fitting, `builder.js` walks the canvas in order (header, sections, footer): for each
  pair, `overlap = collapse ? min(prev.mb, this.mt) : 0`, applied as a negative
  `margin-top` (× scale) on the later host. Recomputed on every refit / reorder / add /
  delete / device switch. Hover outlines and toolbars stay on the section's own box.
- Block library cards are separate, so no merging there.
- Test (browser): two sections with `margin:112px 0 80px` and `margin:112px 0` → gap 112px.

### F2 — attributes (`settings.py`, `sites.py`, `previews.frame`, Builder page template)
- Global readers `preview_body_attrs()` / `preview_html_attrs()` (dicts); profile keys
  `body_attrs` / `html_attrs` override them (whole dict).
- Plain shell: rendered escaped on `<html>` / `<body>`; `class` in `body_attrs` is merged
  with `body_class`.
- Builder pages: `{% prblm_site_body_attrs %}` / `{% prblm_site_html_attrs %}` next to
  `prblm_site_body_class`, only when the page needs the site's assets.

### F3 — marker + reduce motion
- Shell: `<html class="prblm-canvas …">`; template mode: a tiny inline script at the start of
  `{{ prblm_section }}` adds the class (it runs before the section and the site's
  DOMContentLoaded scripts), plus `prblm_preview=True` in the template context so the
  template can add it itself.
- `PRBLM_BUILDER_REDUCE_MOTION`: a `<style>` with `animation/transition` durations and delays
  set to `0s !important` under `.prblm-canvas`; and `scroll-behavior:auto`.
- Builder pages (live) are not previews: no marker there.

### F4 — site matching (`sites.py`)
- `_entry_for(site)`: exact `hostname:port` → `hostname` → `site_name` → first glob
  (`fnmatch`) match in setting order. `choices()` marks sites with no entry; the Block
  library shows "uses the default preview settings" next to them. One `logger.warning`
  per site per process.

### F5 — `docs/PREVIEWS.md`
1. Wrap header, footer, modals, cookie banners and `{% wagtailuserbar %}` in `{% block %}`s
   in `base.html`. 2. Create `prblm_preview.html` (extends base, empties those blocks,
   `{{ prblm_section }}`). 3. One profile per site in `PRBLM_BUILDER_PREVIEW_SITES` (site
   names / wildcards). 4. Alpine / body state (`body_attrs`, or the template). 5. Animations
   (`prblm-canvas`, reduce motion). 6. Page types with their own header/footer: the
   `prblm_builder_chrome_for_page` hook. 7. Checklist: compare canvas vs Wagtail's preview
   (fonts, gaps, animated / JS content). Plus the follow-up's working multi-site setup as
   a full example.

### F6 — release workflow
- `.github/workflows/release.yml`: on `push: tags: ["v*"]` → build wheel + sdist → upload to
  the GitHub release for that tag (create it as a draft if it doesn't exist, so you still
  write the notes). README "Installing on servers": pin the git tag (deploy key / token),
  or download the release wheel and `pip install`.

| # | Topic | Decision |

| G2 | **Usage text** | "Used on N pages" moves to the top-right of each Block library card header; its page list opens below it. |
| G3 | **Card header** | Grey background (#e9ecf1 — darker than section "muted" greys) with a 2px divider line, so it never reads as part of a section. |
| G4 | **Kind filter** | Pills **All · Built-in · Your site's** at the top of the Block library sidebar and of the Layout sidebar's Sections tab (pill style, distinct from the Sections / Page tabs). Only shown when both kinds exist. |

| G6 | **Page tab: where the header/footer comes from** | Describe the real source for this page: the page type's own code (the `prblm_builder_chrome_for_page` hook — "built into this page type; change it in the page's content", or "no separate header"), the site's template (shared by every page of that site that uses it; file name as a small developer hint; per-site), a plugin header (name + Manage link), or none. Never name a template that isn't what the canvas shows. |
| G7 | **Groups** | No code change: document that groups come from the block's own `group` (`class Meta: group = "Heroes"`); blocks without one are listed under "Other". |
| G8 | **Margins on the canvas** | On the **selected** section only: a light striped band over its top and bottom margins, with a small "Space · 112px" label. Nothing on other sections. |

## 7. Technical approach
- **G1:** a tiny script in every preview frame (shell + template mode, next to the
  `prblm-canvas` marker): capture-phase `click` on `a[href]` → `preventDefault()`; `submit` →
  `preventDefault()`. Not on live Builder pages.
- **G2/G3:** `demo.html` card header: left column (name, code, origin, description), right
  column (usage `<details>`; "Not used yet" text). Grey header, border-bottom.
- **G4:** shared pill markup + `fold.js`-style small script; data attribute `data-kind` on
  library cards / nav links and on palette items; search ignores the selected pill (shows
  matches from every kind, with the pill row showing "All" while searching).
- **G5:** `demo.usage(name, block, site=None)` filters pages by `page.get_site()` /
  path under the site's root (`url_path` prefix). `sites.choices()` lists all Sites when
  there's more than one; `?site=all` = everywhere.
- **G6:** `chrome.source(kind, request, page, model)` → `("hook", html)` / `("template",
  name, site)` / `("default", name)` / `("none", None)`, mirroring `chrome.html`'s order;
  `views._chrome_info` builds the text from it. Builder pages keep their dropdowns.
- **G8:** `builder.js`: on selection, two overlay bands inside the section host (top
  `mt × scale`, bottom `mb × scale`), striped with a muted colour, label "Space · Npx" (frame
  pixels), redrawn on refit; `pointer-events:none`.
- Docs: README (groups, kind pills, sites & usage, Page tab sources, spacing bands),
  PREVIEWS.md (links are inert in previews), CHANGELOG 0.8.0, tests.
