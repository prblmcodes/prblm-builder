## 2. Issues, causes, fixes

### 2.1 Site CSS / JS broken in Wagtail's preview (header/footer + own blocks on Builder pages)
- **Cause:** Wagtail renders its preview with a fake request using the Site record's
  hostname / port (e.g. `localhost:80`). `previews._urls` turns `PRBLM_BUILDER_PREVIEW_CSS` /
  `_JS` into absolute URLs with `request.build_absolute_uri`, so in the preview they point at
  the wrong server. The canvas and the live page use the real request, so they're fine.
- **Fix:** root-relative URLs (`static(path)`, e.g. `/static/css/main.css`) for the site's
  assets — in the canvas frames and on Builder pages. Full URLs in the settings are kept as-is.
- **Test:** a Builder page rendered through `make_preview_request` with a Site whose hostname
  differs from the request links the CSS as `/static/…`.

### 2.2 Canvas trims text, the saved section doesn't
- **Cause:** `views._demo_value` trims (for display) the value of a *new* section's canvas
  preview; `layout.new_block_value` saves the untrimmed one.
- **Fix:** trim only for the Block library and the palette thumbnails; canvas previews of new
  sections use exactly the value that will be saved.

### 2.3 Gap under the site header on the canvas only
- **Cause (confirmed):** the frame was sized from `body.firstElementChild`. A plugin header
  starts with its stylesheet `<link>` (height 0), so it fell back to the frame's default
  150px for a 78px header.
- **Fix (done):** `chromeHeight()` measures the bottom of the visible, in-flow elements.

### 2.4 The site's own blocks on the Builder page (`PRBLM_BUILDER_PAGE_EXTRA_BLOCKS`)
Symptoms: demo content differs from the HomePage one, snippet / page fields are empty, the
Block library shows the block twice, no sidebar thumbnail.
- **Cause:** everything is keyed by block **name** (real-content index, Block library
  dedupe, `find_block`). Different names ⇒ treated as different blocks.
- **Fix:**
  - A block key = dotted class path for custom classes (`name` for Wagtail's own generic
    classes). The real-content index and `is_unedited` use it.
  - The Block library dedupes by the same key; it shows the block once, under the first name found.
  - Demo synthesis: snippet choosers (and other model choosers) get the first object of their
    model, as page / document choosers already do.
- **Tests:** the same block class under two names shares real content, is listed once, and
  `is_unedited` still recognises seeded sections.

### 2.5 `wagtail-link-block` (third-party) won't save
- **Not a name clash:** our `LinkBlock` is registered under its own JS path.
- **Cause:** for a block with no real content to copy, synthesised demo content fills every
  text field — including the third-party block's hidden `custom_url`, which has a URL
  validator. Wagtail rejects it on a field that block's own JS hides, so no error is visible.
- **Fix:**
  - URL-ish text fields (`url`, `custom_url`, `link`, `href`…) get a valid URL.
  - Synthesised values are checked with the block's own `clean()`. Child fields that fail are
    reset to their empty default, repeated a few times; if it still fails, the block's
    default is used.
  - (Dropped: a separate save message. With checked demo values, a new section's content is
    always valid, and real content copied from the site was valid when it was saved.)
- **Test:** a block shaped like `wagtail_link_block.LinkBlock` (choice + URL-validated
  `CharBlock`) gets a demo value that passes `clean()`.

### 2.6 Wagtail preview stays stale on the site's own page types until Save draft
- Builder pages update live; HomePage / StandardPage don't until the first Save draft.
- **Not reproduced:** on the test project and on a copy of the site, each section added in
  the Layout tab reached Wagtail's preview within a second (the preview POST carries
  `_pb_layout` and is valid). Likely explanation: the new section is added at the
  **bottom** of a long page while the preview stays scrolled to the top. Waiting for the
  user's re-test.
