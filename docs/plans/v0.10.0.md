# Plan — v0.10.0: publish message, padding bands, smoother tabs

Branch: `feature/v0.10.0` · Status: **done — 0.10.0** · Written 2026-11-12
Source: testing 0.9.1 (same Wagtail 7.0 site).

## Decisions (agreed)

| # | Topic | Decision |
|---|---|---|
| 1 | **Publishing an "Untitled page N"** | Clicking Publish "did nothing": the check used the browser's `confirm()`, which a browser silently answers "Cancel" once "don't allow more dialogs" is ticked. Replace it with an in-page message above the footer: "This page is still called 'Untitled page 5'." — **Rename it** (Content tab, title field focused) · **Publish anyway**. |
| 2 | **Demo content from drafts** | No change: only published pages (drafts may be unfinished / not meant to be seen; the Block library is visible to every admin). The source list updates when a page is published / unpublished / deleted (see 6); a deleted / unpublished page's content falls back to the next-best published use; sections already on pages never change. Documented. |
| 3 | **Padding bands** | On the selected section: its outer element's top / bottom padding as green stripes ("Padding · 64px"), next to the orange margin bands — like browser dev tools. |
| 4 | **Content tab flicker** | Opening the Content tab after a layout change covers it with "Loading the new sections…" at once (no stale sections), then reloads onto the Content tab. |
| 5 | **Tab after saving** | Reopen the tab you saved from (stored at submit, applied as the URL hash before Wagtail's tabs start, so no flash); a failed save still opens the tab with the error. On the Layout tab, a hint "N sections still have demo text — Fill them in" opens the Content tab. |
| 6 | **When demo content is re-read** | Not every 60 s: a cheap check (live page count + newest publish time; seeded records; images; documents), at most every 2 s per process, and a rebuild only when it changed — after a publish / unpublish / delete. Saving a draft changes nothing. A stored per-page index (B) left for very large sites. |
| 7 | **Content tab → Layout tab** | Was: after auto-save only existing frames reloaded (no added / deleted / moved sections); nothing without auto-save. Now: a fingerprint of the stream's form fields (taken whenever the canvas matches the form; canvas-made changes re-take it) shows what changed; with auto-save: cover "Updating the layout…", wait for an auto-save finished after the last edit, clear the form's old `_pb_layout`, reload the canvas. Without auto-save (7.0): bar "You changed the page in the Content tab — Save draft now". |
| — | **Version** | 0.10.0 (minor: new, backwards-compatible features; no migrations). |
